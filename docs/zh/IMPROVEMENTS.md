# 工程增量

问题：B向量流水线会对每段生成行mask，即使一个窄范围条件不可能匹配该段。假设：有序或聚簇数据可利用粗粒度摘要跳过大部分行工作，同时保持计数完全一致、sum在数值容差内一致。

实现：建表时生成数值上下界与有界类别成员摘要。B/C使用同一表、查询和输出，仅prune开关不同；保守判断不可能命中时跳过整段。摘要由验证后的自有数组计算，不信任文件中额外提供的摘要。

预定各规模至少80%求值行减少目标全部达到：94.88%、97.95%、98.72%。全部B/C试次及可选原生DuckDB参考一致。代价为摘要构建、Python元数据和每段检查。打乱顺序后的选择性查询均未减少行数，各规模C均更慢。全量查询也无剪枝；小幅时间差属于计时波动，不据此宣称收益。高基数字符串会主动退回扫描。

该增量将成熟数据库优化机制加入独立维护的小型引擎。DuckDB本身已有统计剪枝，不宣称原创或优于上游。完整协议和负面结果见EXPERIMENTS。
